## 1. 总体结论

**MiniSys 的"安全工程"已经到位,但"风险沟通"完全缺席——引擎装了护栏(GuardRails 四步复验、planHash、隔离区可逆、委派系统命令),仪表盘却没接线。**

决定性的代码事实:`ScanItem` 携带 `riskLevel`(Safe/Cautious/Advanced/InfoOnly)、`dangerous`、`strategy`、`command`、`ruleId` 字段(Scanner.h:27-37),rules.json 27 条规则全部带 `riskLevel/minAgeDays/strategy/detailHint`(rules.json:4-33),但 `src\ui\` 整个目录对这些字段零引用(grep `riskLevel|dangerous|strategy|command|ruleId|detailHint` in src/ui = 无匹配);唯一消费点是 MainWindow.cpp:389 的 `dangerous`,也只产出一句泛化警告。[V]

结果就是用户的三连问:按钮能不能执行(不知道——InfoOnly 项也带复选框,确认后才被拒)、被删的是不是系统文件(不知道——列表无任何风险标识)、删除有没有风险分析提示(没有——确认框只有数量和总大小)。用户真实撞上的 npm-cache 双重失败,错误信息只有一行 Win32 错误码,是这套"零翻译"沟通体系的直接产物。

## 2. 问题清单(按严重度排序)

严重度:P0 阻断 / P1 严重 / P2 一般 / P3 打磨。

### P0(直接损害文件安全信任,应最先修)

**X-1 执行前无法看到"到底会动哪些文件"的清单**
- 位置:MainWindow.cpp:393-401(确认文案只含数量/合计大小);Controls.cpp:32(详情列宽 320px);Presenters.cpp:53(详情列 = detail 文本)。
- 现象:确认框文案为 `将对 %zu 项执行【移入隔离区（可撤销）】操作，合计 %s。…确定继续?`,不含任何路径。用户唯一的路径来源是列表"详情"列——单行 320px,长路径被省略号截断;ListView 未设 `LVS_EX_LABELTIP`/`LVN_GETINFOTIP`,悬停无完整内容 tooltip [I:comctl32 报表视图子项默认无 tooltip]。
- 为什么伤:文件删除工具的确认必须满足"操作前可审计"。用户连"要删 npm-cache 这个目录"都无法从确认框确认,只能靠信任;信任被一次失败(X-4)击穿后无从重建。
- 建议:确认弹窗升级为 TaskDialog(代码库已有 OnAbout 的 TaskDialogIndirect 先例,MainWindow.cpp:500-526),增加"查看将处理的 N 个项目"展开区(完整路径+大小+风险徽标);列表详情列悬停 tooltip(LVN_GETINFOTIP);列宽自适应。
- 收益:确认框从"盲签"变为"可审计清单",直接回应"被删除的文件是不是系统问题"。
- 证据:[V](代码)+[I](tooltip/截断的视觉表现)。

**X-2 风险等级四级数据在 UI 零呈现,列表中 WinSxS/hiberfil 与普通缓存视觉无差异**
- 位置:Presenters.cpp:40-56(RenderItems 只渲染 category/title/size/detail 四列);src\ui\ 无 riskLevel 引用(grep 证据);对照 rules.json:28-33(winsxs/hiberfil/pagefile 均 advanced/info)。
- 现象:Safe(用户 Temp)、Cautious(CBS 日志)、Advanced(WinSxS 委派 DISM)、InfoOnly(pagefile)四类项目在列表里唯一的差别是"默认是否勾选"(recommended,Presenters.cpp:54)。没有风险列、徽标、颜色、图标、分组。
- 为什么伤:预勾选承担了全部风险沟通职责——用户一旦手动勾选 Advanced/InfoOnly 项,就进入无差别盲区;这正是"删除是不是风险分析提示,都没有"的来源。
- 建议:见 §3-B 风险等级可视化方案(风险列 + 徽标 + 行色 + 分组 + 系统组件标注)。
- 收益:30 项结果从"平铺一屏"变为"安全 16 / 谨慎 7 / 系统组件 3 / 仅提示 2"的分层决策界面。
- 证据:[V]。

**X-3 InfoOnly 项(pagefile/swapfile)带可勾选复选框,确认后才被静默跳过——"能不能执行"给出错误答案**
- 位置:Controls.cpp:20-21(全列表 LVS_EX_CHECKBOXES,无法排除行);Scanner.h:34(InfoOnly 定义);GuardRails.cpp:102-105(执行时拒绝:"仅提示项，不可执行");MainWindow.cpp:397(危险警告文案)。
- 现象:页面文件/交换文件行有复选框,可勾选、可通过确认弹窗(⚠ 图标),执行后在结果弹窗里变成 `⊘ 页面文件 pagefile.sys: 仅提示项，不可执行（请参考详情中的指引）`。且确认框的警告例子固定写"如清空回收站",与实际危险项不对应。[V]
- 为什么伤:用户完成"勾选→确认"两步心智承诺后被系统反悔,产生"这工具到底哪些能点"的失控感——用户原话第一句即是此。
- 建议:① InfoOnly 行禁用/隐藏复选框并加"仅提示"徽标(LVS_EX_CHECKBOXES 无法逐行禁用,最简方案:点击行/执行时若选中含 InfoOnly,先行内提示并从计划剔除,配合徽标);② 确认弹窗"不可执行项"单列一档明示"不会处理";③ 警告文案动态点名危险项。
- 收益:消除"确认了却不执行"的信任断裂。
- 证据:[V]。

**X-4 失败信息只有一行 Win32 错误码:无原因、无建议、无重试入口(用户实际撞上 2 次)**
- 位置:QuarantineOp.cpp:17-29(`LastErr(L"MoveFileEx failed")` → "MoveFileEx failed (Win32 5)";`MoveWithRetry` 名不副实,无任何重试);SessionService.cpp:213(结果弹窗行 `× %s: %s`);对照 MoveJunctionOp.cpp:118-126(迁移有 RmGetList 占用预检且错误信息含进程名)。
- 现象:history.jsonl 两条 FAILED note 即用户得到的全部信息。"Win32 5"(ERROR_ACCESS_DENIED)最可能原因是 npm-cache 内文件被运行中的 node/npm/VS Code 进程占用 [I:Win32 语义推断],但 UI 不给任何线索。QuarantineOp 无执行前占用检查(与 MoveJunctionOp 能力不对称)。
- 为什么伤:文件工具的失败沟通是安全感的最后一道防线;错误码等于把调试责任甩给用户。用户重试一次再次失败后放弃(23:52:36 后无第三次)[V 数据]。
- 建议:① 错误码→人话映射表(见 §4-C);② QuarantineOp 执行前 RmGetList 预检,占用时直接提示"被 node.exe 占用,关闭后重试";③ 目录级失败自动降级为逐子项隔离(跳过被锁子项);④ 失败弹窗给"重试失败项"按钮(失败项仍在列表,重试成本低)。
- 收益:npm-cache 案例从"两行天书+放弃"变为"一条可执行建议"。
- 证据:[V](错误串与数据)+[I](占用原因推断)。

### P1(严重)

**X-5 确认弹窗默认按钮是 OK:Enter 即执行删除/清空;不可逆操作确认强度不足**
- 位置:MainWindow.cpp:399-400(执行确认 `MB_OKCANCEL`,无 `MB_DEFBUTTON2`);MainWindow.cpp:486-487(清空隔离区确认同样默认 OK)。
- 现象:两个破坏性确认框,回车都直接落在"确定"上。"清空隔离区"是全应用唯一不可逆文件删除,却与普通确认同强度。
- 建议:全部破坏性确认默认按钮改为取消(`MB_DEFBUTTON2`);清空隔离区升级为 TaskDialog 验证型确认(勾选"我了解此操作不可撤销"后才激活执行按钮)。
- 收益:防误触回车;不可逆操作获得与其后果匹配的确认强度(对标 Windows"永久删除"双重确认)。
- 证据:[V]。

**X-6 手动勾选状态在排序 / 切换 Tab / 执行后全部丢失**
- 位置:Presenters.cpp:41-55(RenderItems = DeleteAllItems + 重插,勾选只按 recommended 恢复);Presenters.cpp:90-108(排序→Refresh);MainWindow.cpp:292(每次切 Tab→Refresh)。

- 为什么伤:勾选是本应用的核心审慎行为(挑选要动哪些文件),静默清空等于惩罚认真核对的用户;LargeFiles 场景排序又是挑选大文件的必然步骤。
- 建议:RenderItems 前按 path 快照勾选集合,重插后恢复;或改用 `LVM_SORTITEMS` 原地排序不重建。
- 收益:审慎操作不再被工具本身抹掉。
- 证据:[V]。

**X-7 确认弹窗文案误导:迁移确认写着"隔离区项目可一键还原";危险警告不点名**
- 位置:MainWindow.cpp:391-398(`action` 为"迁移"时第二行仍固定为"隔离区项目可在"操作历史"中一键还原";危险警告固定"(如清空回收站)")。

- 收益:确认框说的与将发生的一致——风险沟通的第一原则。
- 证据:[V]。

**X-8 进度条定位在客户区外(y=H+2),很可能永远不可见;57-69 秒扫描无百分比、无取消**
- 位置:Layout.cpp:67-70(`int sbTop = H; SetWindowPos(ui.progress, …, sbTop + 2, …)`);对照 MainWindow.cpp:73(窗口 1100×720)、Layout.cpp:9(状态栏自动贴客户区底部,占用 [H-statusH, H])。

**X-9 撤销只能单条:一次隔离 18 项,全部撤销需要 18 轮"选中+点击"**

- 收益:可逆性从"技术上可行"变为"操作上便宜",支撑产品定位。
- 证据:[V]。

**X-10 静默降级:rules.json 解析失败、USN 索引失败,用户完全无感知(真实发生在用户机上)**

**X-11 风险指引文案(detailHint)在详情列中不可读:多行文本被压进单行单元格**

### P2(一般)

**X-12 无键盘可达性:全应用无 WS_TABSTOP、无加速键、无 F5/Enter/Ctrl+A**
