## 0. 一页结论

v2.4–v2.8 把上轮 25 项 L 发现的 P0/P1/P2 主干确实修掉了(12 项抽查全部代码核实,见 §2),危险确认链(TaskDialog+默认取消)、勾选快照、列头切换、worker 化校验/预览是实打实的进步。但本轮以"人体工程学/丝滑"标准复审,发现**键盘通道半残、DPI 半残、info 单通道过载**三类结构性问题:

```
键盘:列表/页签/高级复选框无 WS_TABSTOP → Tab 键永远到不了主列表;
      无 WM_CONTEXTMENU → Shift+F10/Menu 键无右键菜单;Ctrl+A 拦截编辑框文本全选
DPI :manifest 声明 PerMonitorV2 但无 WM_DPICHANGED 处理 → 跨屏拖动后布局错位;
      无 WM_GETMINMAXINFO → 窄窗口按钮行溢出、Apps 页 targetBtn×advancedChk 重叠(<1068 逻辑 px)
信息 :info 标签三写者(说明/仪表盘/hint)互相覆盖;52px 固定高装不下 v2.5 后 4-8 行内容;
      每次 Alt-Tab 回窗都"✓ 列表已校验"刷掉说明区
```

新功能(快速筛选/缓存时间线/四分格状态栏)方向正确,细节缺激活态反馈与重复执行;缓存+复验+空闲刷新的信任叙事已基本成型。

**评分:交互设计 7/10**(上轮 6.5;确认流与勾选保持达标,键盘与 DPI 是当前最大短板)。

## 1. 问题清单(按严重度)

### P1(严重)

**X-1 键盘无法到达主列表、页签条、高级复选框;右键菜单无键盘等价物**
- 位置:[V] MiniSys/src/ui/Controls.cpp:14-20(list)、:129-132(tree)均无 WS_TABSTOP;:60-62(advancedChk)、:90-98(editFileType/editDrives)同样缺失;MainWindow.cpp:147-151 手写 Tab 导航只走 GetNextDlgTabItem;grep 全仓无 WM_CONTEXTMENU。
- 现象:Tab 键在 13 个按钮/编辑框间循环,**永远进不了 1000 行的结果列表**(方向键/Space 勾选因此不可达);页签条(WC_TABCONTROL 无 WS_TABSTOP)无法聚焦 → Ctrl+Tab 切页失效;Shift+F10 与 Menu 键在列表上无反应(右键菜单只挂在 NM_RCLICK)。
- 为什么伤:这是"键盘优先"评审维度的硬伤——高级用户(本工具的目标人群)用键盘走查列表是最快路径,现在必须先鼠标点一下列表;纯键盘用户完全无法操作。
- 建议:① list/tree/tab/advancedChk/editFileType/editDrives 补 WS_TABSTOP;② WndProc 加 WM_CONTEXTMENU(用消息自带坐标,-1 表示键盘触发,取焦点项矩形中心弹 OnListContextMenu/树菜单);③ 消息循环加 Ctrl+Tab → TabCtrl_SetCurFocus+模拟切换。
- 收益:键盘全链路可达;与 Fitts 无关但属同一"操作丝滑"契约。工作量 S。

**X-2 Ctrl+A 全局拦截了编辑框的文本全选**
- 位置:[V] MainWindow.cpp:138-141 加速表 `{FVIRTKEY|FCONTROL,'A',IDC_ACCEL_SELECTALL}`,消息循环 :144-145 `TranslateAcceleratorW` 先于 Dispatch。
- 现象:焦点在 editSearch(或大文件页 editFileType/editDrives)按 Ctrl+A,触发的是**切换全列表勾选**(OnSelectAll),而不是选中输入框文本——想全选替换查询词的用户会看到列表勾选被意外翻转。[机制 V;EDIT 控件本身是否响应 Ctrl+A 依 Windows 版本,I]
- 为什么伤:搜索页是高频页,改关键词的常规操作(Ctrl+A→输入)变成破坏性副作用(勾选状态被改),与 L-1 努力保住的"用户勾选意志"直接冲突。
- 建议:加速表命中后先判 `GetFocus()` 是否 EDIT 类(`GetClassName=="Edit"`),是则放行给控件;或 IDC_ACCEL_SELECTALL 处理里检查焦点。
- 工作量 S(10 行内)。

**X-3 每次回窗口都"✓ 列表已校验"刷掉 info 区,且与状态栏双通道重复**
- 位置:[V] MainWindow.cpp:427-430(WM_ACTIVATE→400ms TIMER_VERIFY_LIST)、:611 `ShowHint(L"✓ 列表已校验，未发现已删除的项目。")`;SessionService.cpp:796-798 状态栏 pane2 同时报"校验完成：列表均为最新"。
- 现象:用户每 Alt-Tab 回窗口,v2.7 校验跑完后 info 标签被这句提示**永久覆盖**——垃圾页的"可释放 X GB"仪表盘、"上次扫描"时间线、三条页说明全部消失,直到下次切页/扫描。信息是双通道重复的(pane2 已有),而代价是抹掉了主信息区。
- 为什么伤:info 区是本应用唯一的"仪表盘+说明"承载;被一条低价值常态通知反复清空,等于仪表盘大部分时间不可见。也违反自己定的反馈规范("info 一件事一句话")。
- 建议:校验无死者→完全不提示(静默成功),或仅 pane2;有移除时才动 info。顺手把"校验中"从 pane2 保留即可。
- 工作量 S。

**X-4 PerMonitorV2 声明了 WM_DPICHANGED 却不处理**
- 位置:[V] MiniSys/src/res/app.manifest:27(dpiAwareness=PerMonitorV2);grep MainWindow.cpp 无 WM_DPICHANGED/WM_SETTINGCHANGE。
- 现象:窗口拖到另一 DPI 显示器:系统发 WM_DPICHANGED(附建议矩形),未处理 → 窗口物理尺寸不变,但 GetDpiForWindow 已返回新 DPI → 下一次 OnSize/OnTabChanged 的 LayoutWindow 用新 Scale 重排:控件变大而窗口没变大 → 按钮行溢出、advancedChk 越界、列宽突跳。[触发链 V,视觉后果 I]
- 为什么伤:UiScale 体系(P2-4/L-12)建到 95%,差最后一条消息;双屏用户(笔记本+外接,常见 100%+150%)每次跨屏必现。
- 建议:`case WM_DPICHANGED: SetWindowPos(hwnd_, nullptr, 建议RECT...); LayoutWindow(...)` 一处补齐(用 lParam 的 RECT)。
- 工作量 S。

**X-5 无最小窗口尺寸;窄窗下按钮行溢出、Apps 页两控件重叠**
- 位置:[V] grep 无 WM_GETMINMAXINFO;Layout.cpp:54-67 坐标数学(96dpi 换算):scan[8..148] exec[156..316] undo[324..484] open/emptyQ[492..632] targetBtn/sortSize[640..820/780] sortTime[788..928];advancedChk=W-248 右锚(:60-65)。
- 现象:① 窗口宽 <936 逻辑 px 时 btnSortTime 被裁;② **Apps 页 targetBtn(640..820)与 advancedChk(W-248..W-8)在 W<1068 时重叠**——默认 1100px 只有 32px 余量,用户随手缩一点窗口两控件就叠上(这是 L-4 修复后残留的真实碰撞对;题面猜的"advancedChk×btnSortTime"不成立,见 §3);③ 矮窗时 contentH=H-contentY-statusH-pad 可为负(SetWindowPos 负高,列表行为异常);④ About 按钮(W-84,Layout.cpp:51)在窄窗与最后一个页签重叠。
- 建议:WM_GETMINMAXINFO 设最小 960×560 逻辑 px(经 UiScale);或改自适应(按钮行两行/收纳进溢出菜单)。
- 工作量 S(最小尺寸)/ M(自适应)。

### P2(一般)

**X-6 info 标签 52px 固定高装不下 v2.5 以来的内容(⚠ 危险项说明沉底)**

**X-7 RenderItems 全量重建:选中/焦点/滚动/用户列宽/排序全部不保持(L-1 只修了勾)**

- 现象:排序、切页回来、校验移除幽灵行、每次搜索击键 → 列表回到顶部、无焦点、列宽被重置为默认。1000 行结果里翻到 500 行,切去历史页再回来,位置丢失。

## 4. 理想交互蓝图(Win32 现实约束内)

1. **焦点稳定性契约**(治 X-7):任何 RenderItems/Refresh 必须保持 {滚动顶行, 焦点项, 选中集, 列宽, 排序}。实现为一对 helper(PreserveViewState/RestoreViewState,按路径键),列宽只在列集变化时重置。这是"丝滑"的底座——之后所有重渲染路径(搜索、校验、缓存恢复)自动受益。
2. **非模态通知中心**:info 区拆成两个通道——第 1 行"瞬态状态"(hint,8 秒后自动回落到常驻内容,或由 pane2 承担),第 2 行起"常驻说明+仪表盘"。所有 ShowHint 调用点收敛为 `Notify(text, Important|Transient)`;Transient 不覆盖常驻区。落地形态:把 info 拆成两个 STATIC(高度 22+剩余),代码量小。
3. **陈旧数据标记规范**:缓存结果除"上次扫描: X 前(缓存)"文案外,给列表 header 或标题栏加轻量标记(如列头"项目(缓存)"或行尾灰色 ⧗);数据>30min 且未自动刷新时 pane1 显示"⧗ 数据已过期"。一套标记,三处复用(缓存恢复/空闲刷新前/校验后)。
4. **过滤可视化(chips)**:查询框正下方(或内嵌)显示激活 token 的小按钮"ext:pdb ✕""folder:debug ✕",点击即移除并重搜;快速筛选菜单同步 MF_CHECKED。把"有过滤在生效"从需读QueryBox变成一眼可见——Everything 的过滤器栏即此模式。
5. **命令面板(可选,远景)**:Ctrl+K 弹出无边框顶层窗口(edit+ListView),数据源=固定命令表(扫描/重建索引/切六页/快速筛选/清空隔离区/关于)。Win32 实现约 200 行,一次投入把所有"藏深的功能"(预览执行、刷新列表、排除)拉到零层级。与现有加速键不冲突。
6. **键盘契约**(治 X-1/X-2):所有可交互控件 WS_TABSTOP;EDIT 聚焦时 Ctrl+A 归控件;列表 Space 勾选/Enter 打开;Shift+F10=右键;Ctrl+Tab 切页;Esc 在搜索框=清除。写成一条注释契约放 MainWindow.h 顶部,防回归。
7. **危险确认的最后一公里**(治 X-13):确认 TaskDialog 增加"查看 N 个项目"展开(展开区放等宽字体路径清单,可复制);Apps 迁移确认额外列"目标: D:\MigratedApps(剩余空间 X)"。

## 7. 建议人工复核清单(现有运行实例,约 5 分钟;均为 [I] 项)

1. **键盘走查**:点列表后按 Tab 一圈,确认列表/页签确实进不了 Tab 序(X-1);列表上按 Shift+F10 确认无菜单。
2. **Ctrl+A 冲突**:焦点在搜索框按 Ctrl+A,观察是选中文本还是翻转列表勾选(X-2)。
3. **窄窗重叠**:窗口缩到约 1000px 宽,切"应用迁移"页,看"选择迁移目标盘…"与"高级模式(Symlink)"是否重叠(X-5;注意先选个目标盘才有长文本,或直接看按钮矩形)。
4. **跨屏 DPI**:若有 100%+150% 双屏,拖窗口过界,看按钮/列宽是否错位(X-4)。
5. **Alt-Tab 噪声**:正常浏览后切走再切回,确认 info 区是否变成"✓ 列表已校验…"且仪表盘消失(X-3)。
6. **info 折叠**:垃圾页空闲态数 info 可见行数,确认"⚠ 危险项…"第 4 行是否被裁(X-6);150% DPI 下复核。
7. **执行按钮截断**:全选 20+ 项,看"执行选中操作(N 项 · X GB)"末尾是否被裁(X-15)。
8. **空闲重扫**:放置 5 分半钟(勿动键鼠,可看窗口),观察自动扫描启动时列表是否被禁用、回来时是否有惊吓感(X-10)。
9. **快速筛选激活态**:套用 .pdb 后再开菜单,确认无勾选标记(X-8)。
10. **时间排序**:大文件页点"按时间排序",看箭头是否落在"详情"列且用户能否理解(X-9)。
