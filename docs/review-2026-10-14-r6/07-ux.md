## 0. 一页结论

三项用户反馈（Tab 选中加粗 / 信息条排版 / 全行大小）**全部落地且经放大截图验证有效**；上轮 P1/P2（X-26..X-31）修复全部存活。但本轮像素实测抓到**一个 P0：虚拟列表的行首复选框完全不渲染**（状态图标槽位被保留、行文字右移 16px，但槽内像素纯白 min=255——所有列表页的"勾选→执行"主回路失去了可视抓手，两份 v2.19 实拍截图一致复现）。上轮评审第 8.2 节曾预言"虚拟列表勾选路径 comctl 语义有版本差异——上机第一件事试勾选"，本条即为该风险的实证。

## 1. 问题清单（本轮新发现 X-41 起，按严重度）

### P0

**X-41 列表复选框不渲染：勾选状态完全不可见（v2.15 虚拟列表改造的遗留回归）**
- 现象 [V-像素]：对 minisys-current.png 逐行测量状态图标槽位（x≈18–36，数据行文字从 x=40 起，较表头 x=24 右移 16px=标准 state-image 槽）：**5 个数据行槽位全部纯白（min=255，<220 像素数=0）**；而同窗口搜索行的"匹配完整路径"复选框区有 154 个暗像素——控件具备画框能力，唯独列表行不画。第二份实拍 .tmp-shots/info-strip2.png（v2.19 时代）同样四行全空，vision 独立判读两份截图结论一致。
- 为什么伤：工具主回路是"勾选→执行选中操作"。勾选仍有三条暗通道（点击空白槽 NM_CLICK 命中 LVHT_ONITEMSTATEICON、Space、Ctrl+A——[V] MainWindow.cpp:247-259/441-455/549-561），但**用户看不见哪些行已勾选**：Ctrl+A 全选后只能盲信确认清单；单行勾选则无任何视觉确认。Fitts 意义上这是一个"看不见的目标"。
- 代码事实 [V]：Controls.cpp:27-35 `LVS_OWNERDATA | LVS_EX_CHECKBOXES` 同开；Presenters.cpp:204-212 SupplyDispInfo 对 `LVIF_STATE` 正确回 `INDEXTOSTATEIMAGEMASK(checked?2:1)`。响应写了、字形不画，指向 comctl6 在 owner-data 下 state image list 的创建/绘制路径（[I] 根因；上轮报告 §8.2 已点名此风险未活体验证）。
- 改法（按验证顺序）：① 上机 5 秒确认（见 §7）；② 若复现，最稳修法是放弃 LVS_EX_CHECKBOXES 的内置框，在 NM_CUSTOMDRAW CDDS_SUBITEM|prepaint 对第 0 列自绘 DFCS_BUTTONCHECK（主题感知、高对比度自动正确），或给 LVM_SETIMAGELIST(LVSIL_STATE) 显式挂一张含两态框的位图图列；③ Space/Ctrl+A 路径保持不变。工作量 M（含回归 6 页）。
- 预期收益：恢复主回路可视性；同时顺带解决"复选框在高对比度下随主题"的问题。

### P1

**X-42 RootsDlg「浏览添加…」静默失效：GetDlgItem(h,1) 取到的是"确定"按钮**
- 位置 [V]：MainWindow.cpp:1134 `HWND edit = GetDlgItem(h, 1);`——R-1 修复时编辑框已改 id=1001（:1201），但浏览分支仍按旧 id=1 取控件，而 id=1 == IDOK == "确定"按钮。后续 EM_SETSEL/EM_REPLACESEL 发给 BUTTON 全部无效：**选完目录后编辑框毫无变化**，无提示。上轮 X-26 修的是"多行保存丢数据"，本条是同一对话框的另一处坏点，且正是 X-26 修复引入 id 变更后未同步的调用点。
- 为什么伤：「浏览添加…」是该对话框鼓励的主输入方式；静默无效让用户以为功能坏了（事实上确实坏了）。
- 改法：`GetDlgItem(h, 1001)`（1 处）。S（5 分钟）。上轮报告还建议的"OK 前就地校验标红无效行"仍可一并做。

**X-43 DrawInfoText 无高对比度豁免：v2.19 自绘信息条在 HC 主题下可能不可读**
- 位置 [V]：MainWindow.cpp:119-178。列表风险染色有 HCF_HIGHCONTRASTON 豁免（:387-391，X-14），但同样新引入自定义色的信息条没有：固定 FillRect COLOR_BTNFACE + 首行 0x1A1A1A/灰 0x5A5A5A/琥珀 0xB25000。高对比度黑色主题下 BTNFACE 近黑，0x5A5A5A 灰字近乎隐形；改造前的普通 STATIC 由系统配色，不存在此问题——这是 v2.19 的无障碍回归。
- 改法：DrawInfoText 开头查 SPI_GETHIGHCONTRAST，HCF 时全部用 GetSysColor(COLOR_WINDOWTEXT/COLOR_BTNFACE) 并保留行距/加粗排版。S。

**X-44 执行阶段不可取消：Delegate（DISM/powercfg，分钟级）进行中无任何取消入口**
- 位置 [V]：SetTaskBusy（MainWindow.cpp:1655）在 Executing 时禁用扫描按钮；OnScan 的取消只认 IsScanning()（:1486）。F5 同路。即：普通扫描可取消（v2.5 X-8 修复），**执行链一旦开始只能等**。批量隔离 rename 通常毫秒级可忍，但 WinSxS 委派 DISM /StartComponentCleanup 文档级耗时数分钟——About 文案自己都写明（:2040）。
- 改法：Executing 时把扫描按钮再兼作"取消执行"（SessionService 侧在计划项间检查 cancelScan_；委派子进程 TerminateProcess 需谨慎——至少支持"完成当前项后停止"）。M。

### P2

**X-48 大文件页参数修改后零反馈：无"需重扫"提示、Enter 不触发扫描**

**X-49 快速筛选/搜索框的 busy 分支文案与静默**

- 改法：按 taskMode_ 分支文案（Executing→"执行完成后请再点一次"；Scanning→"扫描完成后可应用"）；Indexing 中 Enter 给"索引构建中，完成后将自动搜索"。S。
