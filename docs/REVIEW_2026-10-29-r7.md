## 0. 一页结论

**用户投诉「清理隔离区，完成之后，下面的列表信息还未清空」的完整因果链（四路独立证实：主审 + 04 + 05 + 07）：**

1. **毒名字文件**：10-06 第 3 轮评审代理的沙箱实验把一个尾点名文件 `tdot.` 真移进了 `C:\MiniSys.Quarantine`。尾点/尾空格名不带 `\\?\` 前缀时 `DeleteFileW` 直接 err 2 —— **普通 API 永远删不掉它**。
2. **remove_all 全盘连坐**：`fs::remove_all` 遇到它删光其余全部内容、却对整盘返回 ec=145 失败 → `RunEmptyQuarantine` 的"逐盘判定"把该盘记为失败 → **标记 `[已释放]` 的循环整个跳过**（真机实证：84 条 QUARANTINE 记录 0 条已释放）。
3. **状态列撒谎**：即使标记成功，历史行仍显示「已隔离 · 成功」「可还原」（`HistoryTypeLabel`/`HistoryRiskLabel` 不识别 `[已释放]`），撤销预检也放行 → 用户被引去点必然失败的「撤销」。
4. **用量从不对账磁盘**：状态栏一直宣称「73 项 / 4.45GB（清空后释放）」，而隔离区实际早已空——每次点「清空」都"成功 0"零动作，纹丝不动。

**同根类的其他「低级错误」（全部当轮修复）**：Ctrl+K 自 v2.22 被加速表计数 bug 掐死（4 项只注册 3 项）；内置「Debug/Release/bin/obj 文件夹」四个快速筛选**从未工作过**（预设生成 `folder:debug`，解析器只认裸 `folder:` → 恒 0 命中——这正是用户当天点 49 秒索引重建的导火索）；**手动重建索引的成果永不落盘**（force 分支提前 return 绕过落盘 + WalkBuild 内部落盘发生在 valid_ 置真之前恒 no-op）；**测试套件自 10-11 起向真实用户 history.jsonl 写了 49 行幽灵记录**（TrustChain 测试未重定向路径）。
