## ① 整体印象(三句话)

1. 这是一个"信息都在、全靠文字"的工具:全部视觉重量压在单一 9pt 正体黑字上,自定义颜色全 UI 仅 3 个暖色文字值,语义层次靠 emoji/符号前缀让文字自己解释自己——扫一眼找不到"能释放多少空间"这个核心答案。
2. 有效截图中列表几乎全空,60-75% 的窗口面积是纯白空白且无任何空状态设计,首屏气质是"未完成"而非"就绪";唯一稳定出现的饱和色是"关于"按钮的蓝色问号(shot-14:第一视觉落点)——装饰元素抢走了语义元素的色。
3. 骨架其实规整(8px 栅格、DPI 缩放、列结构、状态栏分区都已在位),欠的是最后一层"视觉语义化":数字列左对齐、三套图标语言混用、同字号文字墙当仪表盘——这三件事不动布局机制就能修。

## ② 八维审计

### 1. 视觉层级
**现状**:六层结构——标题栏 / 28px 页签行(右嵌"关于…")/ 30px 按钮行(每页 2-5 个控件)/ 自适应信息文字墙(1-6 行,15px 行高)/ 列表 / 四格状态栏。全部同一字号字重。
**问题**:
- 核心指标埋在正文里:"可释放:安全 X 项 / Y GB,谨慎 Z 项 / W GB"(MainWindow.cpp:1377)与静态说明文字同字号同色,3 秒扫视抓不到(Junk 页文字墙常态 4 行、扫描后可达 6 行)。
- 空列表占窗口 2/3~3/4 却零信息,层级倒挂:"最大的区域传达最少的内容"(shot-01/02/03/04,Confirmed)。
- 活动态计数反而最显眼:"执行(11 项·1.31GB)"是 shot-03 页面信息密度最高的元素,但列表体为空,按钮与画面矛盾(shot-03,Confirmed;属视觉一致性问题,裁剪/渲染根因由几何线同事判定)。
- 页签活动态弱:多帧分析无法辨认哪个页签选中("no clear visual highlight",shot-08/12 弃用帧下观察;经典 tabcontrol 固有,Likely)。
**证据**:shot-01/02/03/14(Confirmed);MainWindow.cpp:1360-1411、Layout.cpp:114-142。

### 2. 色彩系统
**现状**:仅 3 个自定义色,全为整行文字色(NM_CUSTOMDRAW,MainWindow.cpp:290-297):系统组件橙 `B25000`、仅提示灰 `888888`、谨慎暗黄 `705A00`(仅外置规则行);Safe 无色。按钮/页签/状态栏/进度条全系统默认灰。界面彩色来源:风险列 VS16 彩色 emoji 徽标 + stock 图标自带色 + 蓝问号。
**问题**:
- 危险谱系不完整:最高危"清空回收站(不可逆)"与"系统组件"同为橙字;Safe(建议执行的默认项)反而无任何视觉鼓励。
- 色彩未服务核心指标:可释放空间、系统盘可用量(状态栏)都是纯黑文字。
- 唯一饱和色给了装饰:关于按钮蓝问号成为全窗第一视觉落点(shot-14 原文"the eye lands first on those blue circles",Confirmed)。
- 状态栏四格无任何语义着色/图标,中格"隔离区: 50 项 / 2.13 GB"与"就绪"同权。
**证据**:MainWindow.cpp:290-297(Confirmed,代码);行染色实际观感因无带数据的垃圾页截图标 Likely;蓝问号 shot-14(Confirmed)。

### 3. 字体与排版
**现状**:所有控件统一 `lfMessageFont`(Segoe UI 9pt)单一字号单一字重(Controls.cpp:146-160);信息区 STATIC `DT_WORDBREAK`;大小 `"%.2f GB"`(StringUtils.cpp:26-38);时间 `"%02d-%02d %02d:%02d"`;计数另有千分位("3,030,729")。
**问题**:
- **数字列左对齐**:全部 6 列 `LVCFMT_LEFT`(Controls.cpp:34,Presenters.cpp:249),"1.66 KB / 160.59 MB / 219.67 MB"无法按位对齐比较(shot-14 大小列,Confirmed)——大小是本工具的核心量化列,这是排版上最大的单点损失。
- 千分位不一致:索引用"3,030,729"、大小用"474.81 GB"无千分位,同一状态栏两种数字习惯。
- 信息区无字重层级:标题性内容(如"⚠ 危险项…")、数据(dashboard)与说明文字完全同权;列头与内容字号相同(靠系统列头样式仅弱区分)。
- 大小/时间列宜用等宽或 tabular 数字,防止"1.11 GB"与"888 MB"宽度抖动(现状比例字体,排序刷新时列内数字左边缘齐但右边缘参差,Likely)。
**证据**:Controls.cpp:33-47;StringUtils.cpp:26-38;shot-14(Confirmed)。

### 4. 图标系统
**现状**:三套视觉语言并存——
  a) stock 彩色 16px 图标:扫描=SIID_FIND(放大镜)、撤销=SIID_FOLDERBACK、清空隔离区=SIID_RECYCLERFULL、打开=SIID_FOLDEROPEN、迁移目标=SIID_DRIVEFIXED、关于=SIID_HELP(蓝圆问号);
  b) VS16 彩色 emoji 徽标(风险列):`🛡️ 安全 / ℹ️ 谨慎 / ⚠️ 系统组件 / ⚠️ 不可逆 / ℹ️ 未评估`(Presenters.cpp:357-364,显式追加 U+FE0F);
  c) 无 VS16 单色文本符号(历史状态列+信息区):`⧗ 未签名 / × 需关注 / ⚠ 不可逆 / 🛡 可还原 / ⊘ 仅提示 / · △ → ✓`(Presenters.cpp:879-884 等)。
**问题**:
- **同一符号两种渲染**:风险列 `🛡️`(彩色 emoji)与历史状态列 `🛡`(单色字形)在不同页表达同一"安全"概念,视觉上是两个符号——shot-14 中单色盾被视觉分析误读为"月亮🌒",可辨识度实损(Confirmed)。
- 作者已在代码注释承认该机制脆弱(Presenters.cpp:350-352:"without it 🛡/⚠ can render as a monochrome box depending on the installed font set")——字体环境相关渲染=不可控视觉。
- stock 图标风格不统一:彩色照片感回收站、蓝色圆形问号、线性放大镜同排一行(shot-01 撤销=橙黄文件夹、清空=蓝色图标,Confirmed);16px 图标在 30px 按钮内占比约 53-60%,偏小且彩色图标成为按钮行主要色源。
- `⧗ 未签名`的沙漏符号语义(等待/时间)与实际含义(记录缺签名)错位。
**证据**:shot-01(stock 混排)、shot-14(单色盾误读)(Confirmed);Presenters.cpp:350-364/879-884(Confirmed,代码)。

### 5. 间距与密度
**现状**:8px 基准栅格:pad=8、按钮 30×140px、页签 28px、信息行高 15px、按钮间距 8px(Layout.cpp:43-67);按钮行每页最多 5 控件(垃圾页:扫描/执行/打开/按大小/按时间;应用页:扫描/执行/打开/选择迁移目标+右锚"高级模式"勾选);列表行高系统默认 ~17px;状态栏 340/660/自适应/220px 四格。
**问题**:
- 按钮等宽等权:主操作"执行"与低频"按时间排序"同为 140px 灰按钮,主次不分(shot-02/03,Confirmed)。
- 状态栏右侧常空:第 4 格 220px 只在任务中显示进度条,空闲时整条空白(shot-01,Confirmed)。
- 列表无列分隔(未设 LVS_EX_GRIDLINES),分类/风险/项目三列都是长中文串,横向扫读列边界靠列头记忆(Likely)。
- 好的一面:8px 栅格执行得相当一致(全 magic number 均为 4/6/8/12 的倍数,DPI 缩放统一),这一层不需要返工。
**证据**:Layout.cpp:43-67、MainWindow.cpp:1218-1229;shot-01/02/03(Confirmed)。

### 6. 状态与反馈的视觉设计
**现状**:忙碌态=状态栏第 4 格 marquee 进度条(25ms,PBS_SMOOTH)+扫描按钮图标换 SIID_DELETE+第 3 格 ProgressText;总量已知后切 PBM_SETPOS 百分比;空闲第 3 格"就绪";结果反馈为信息区文字"✓ 完成: 成功 X · 跳过 Y · 失败 Z"。
**问题**:
- 忙碌/空闲的窗口级视觉差极小:仅状态栏一角变化,按钮行/页签/标题栏不动,截图无法区分"刚完成"与"从未扫描"(shot-01/02/14 空闲态均无任何"上次任务结果"的视觉残留,Confirmed)。
- 进度文本(第 3 格)与进度条(第 4 格)分离,阅读时视线要跨一格(Likely,机制代码 Confirmed)。
- 三种结果徽标 `✓ / × / ⧗` 中两个是纯文本符号、历史页混排 emoji `🛡`,同一列四种符号语言(见第 4 维)。
**证据**:MainWindow.cpp:436-455/1449-1467、Controls.cpp:78-81(Confirmed,代码);运行中观感 Likely(截图未捕获扫描帧)。

### 7. 信息区(文字墙)专项
**现状**:信息区是唯一"仪表盘",但形态是 3-4 行同字号纯文本,首行随场景拼接:缓存时间行 → dashboard → 降级通知 → 静态页说明(MainWindow.cpp:1357-1411),上限 6 行。
**问题**:说明文字(教用户怎么用,长期不变)与状态信息(本次扫描结果,频繁变化)同区同权;一句 60+ 字的长句(`"扫描系统/浏览器/开发缓存等可清理项;勾选后执行将移入隔离区,可在"操作历史"一键还原。"`)在小字墙上不可扫读(shot-03/12,Confirmed)。

### 8. 整体气质判断
现状是典型"工程师工具":忠实、密集、零装饰,但也零引导——像 2003 年的 Sysinternals,而不是 2026 年的 Everything/Process Explorer(两者都在保持原生控件的同时用:数字右对齐、状态列着色、主按钮强调、空列表提示)。方向应是"经典 Win32 的克制现代版":不动布局机制,补上视觉语义层。

## ③ 设计方向提案(≤8 条,按 视觉收益/成本 排序)

| # | 改动 | 现状 → 目标 | 实现要点(纯 Win32) | 量 |
|---|------|------------|--------------------|----|
| P1 | **数字列右对齐** | 大小/时间全列 LVCFMT_LEFT,"1.66 KB"与"219.67 MB"无法对位 → 数字列右对齐,一眼比较 | `AddCol`/`SetListColumns` 对"大小/时间"列设 `LVCFMT_RIGHT`(列头自动右对齐);OWNERDATA 下零额外成本 | S |
| P2 | **空列表状态设计** | 空列表=纯白 60-75% 面积 → 居中灰字引导("尚无结果 — 点击「扫描」开始"/搜索页"输入关键词开始搜索") | 列表区叠一个居中 `SS_CENTER|SS_CENTERIMAGE` 灰字 STATIC(父窗口 `WM_CTLCOLORSTATIC` 给 `SetTextColor(COLOR_GRAYTEXT)`),行数==0 时 ShowWindow;不碰 ListView | S |
| P3 | **徽标语言统一为单色文本符号+语义染色** | 风险列彩色 emoji(🛡️/⚠️)与历史列单色符号(🛡/⚠)并存、同义不同形 → 全部去 VS16 单色符号,风险等级靠已有的三个文字色表达 | `RiskBadge()` 移除 U+FE0F;NM_CUSTOMDRAW 把"整行染色"收窄为"仅风险列染色"(`CDDS_SUBITEM` 阶段按 `iSubItem==1` 设 `clrText`)——顺带解决高对比模式下彩色 emoji 不可读 | S |
| P4 | **风险色阶补全四级** | Safe 无色、不可逆与系统组件同橙 → 安全=绿(或默认+✓)、谨慎=暗黄、系统组件=橙、不可逆=红 | `RiskBadge`/染色 switch 增加 EmptyRecycleBin→`RGB(0xC0,0x00,0x00)`;Safe 给 `RGB(0x1F,0x7A,0x1F)` 或保持默认黑;仅改一处 switch | S |
| P5 | **信息区拆"指标行+说明行"** | 3-6 行同字号文字墙当仪表盘 → 首行=加粗 11pt 指标("可释放 3.4 GB · 已隔离 2.13 GB"),其余降为 8pt 灰说明,压到 2 行 | 拆两个 STATIC:指标行 `CreateFontW(-15,0,0,0,FW_BOLD,…)`;说明行 `WM_CTLCOLORSTATIC` 灰字;`Layout.cpp` 的 DT_CALCRECT 自适应逻辑复用 | M |
| P6 | **主/危按钮分层** | 扫描/执行/清空隔离区等宽等权 → 执行=行内唯一强调,清空隔离区=警示 | 执行按钮 `SetWindowLong` 加 `BS_DEFPUSHBUTTON`(系统粗边框,零成本)+FW_BOLD 字体;清空隔离区标题改"⚠ 清空隔离区(永久删除)"或 owner-draw 红字;排序按钮缩窄为 90px 降为次级 | S-M |
| P7 | **忙碌态窗口级可见** | 仅状态栏一角 marquee → 扫描中标题栏加"[扫描中…]"前缀、扫描按钮文字换"取消扫描" | `SetWindowTextW(hwnd_, L"[扫描中] MiniSys — …")`;按钮已有图标切换,补文字;进度文本与进度条同放第 3-4 格合并为"格 3 文本+格 4 bar"现状已近,可不动 | S |
| P8 | **stock 图标线性化(可选)** | 彩色照片感 stock 图标混排,蓝色问号抢焦点 → 统一 16px 单色线性图标 | 成本最高:需自绘/内嵌单色 ico 资源;**降级方案**:仅移除色彩最重的 SIID_HELP(关于按钮去图标,文字即可)与 SIID_RECYCLERFULL,保留线性 SIID_FIND/FOLDEROPEN | M |

排序理由:P1-P4 都是"改字符串/一个 fmt/一个 switch"级别的 S 量,却分别修复"核心数字不可比/首屏空白/符号同义不同形/危险不分级"四个最痛的点;P5 收益同样大但要动布局文件;P6/P7 是姿态修正;P8 收益/成本比最低,可只做降级方案。

## ④ 不建议动(避免过度设计)

1. **8px 栅格与按钮尺寸体系**(pad=8/btnH=30/btnW=140/DPI 缩放):四轮迭代已打磨到位,视觉上规整,重调只有风险没有收益。
2. **经典 tabcontrol 本体与"关于"右嵌布局**:页签视觉弱是控件固有,自绘页签成本高;信息架构(6 页签)已成熟。
3. **状态栏四格结构与进度条覆盖第 4 格**:v2.5 专门修过位置,结构合理,只需内容着色不要动结构。
4. **列表行为(LVS_OWNERDATA/checkbox/全行选择/双缓冲/LABELTIP)**:性能与可用性已验证,视觉层不碰机制。
5. **深色模式/Fluent 风格/自绘全套控件**:纯 Win32 无第三方库前提下的成本黑洞,且 commctrl v6 深色支持不完整——明确出界。
6. **信息区的文本内容本身**:文案质量高(诚实、有行动指引),问题只在呈现层级,不要删内容。

## ⑤ 每条的人工复核方式

| 条目 | 复核步骤 |
|------|---------|
| P1 | 打开垃圾清理页(有数据),看"大小"列数字是否右对齐、个十百位可垂直对位;点列头排序后数字边缘不抖动 |
| P2 | 新会话进搜索页/历史页,列表应出现居中灰字提示;出结果后提示消失且不挡列表 |
| P3 | 并排截图对比垃圾页"风险"列与历史页"状态"列:盾形/警告符号应为同一单色形状;高对比度主题下风险列仍可读 |
| P4 | 勾选"清空回收站"行 → 风险列文字变红;"安全"行有正向色或保持黑;橙/黄/红/灰四级肉眼可分 |
| P5 | 完成一次扫描:信息区首行应为加粗大字指标,说明文字变灰变小;窗口拉窄时不与列表重叠(DT_CALCRECT 自适应仍生效) |
| P6 | 执行按钮应为按钮行唯一强调(粗边框/粗体);"按大小/时间排序"明显退为次级;危险按钮有警示标识 |
| P7 | 触发扫描:标题栏出现"[扫描中]"、扫描按钮变"取消";空闲后恢复;与状态栏 marquee 不冲突 |
| P8(降级) | 按钮行剩余图标风格一致(线性);关于按钮无图标后不显突兀 |
