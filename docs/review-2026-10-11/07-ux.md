## 0. 一页结论

v2.10→v2.14 把上轮蓝图的三件大事真正落了地:命令面板(Ctrl+K)、确认清单(X-13)、视图状态保持(X-7),加上修改时间列、空闲倒计时、会话恢复,主干交互明显成熟。但本轮以新功能交互为主轴走查,发现**一个功能性 P1 与一条三段断裂的"旧记录信任流"**:

```
P1  开发缓存根对话框:两处 `flush;`(漏写调用括号)→ 多行输入在“确定”时
    整体拼接成一个非法路径被丢弃,且原配置被清空,还弹出 ✓ 成功文案
P2  信任流断裂:历史页对未签名记录仍标“🛡 可还原” → 撤销才被拒 → 拒绝提示
    引用的命令名与面板项名不一致(按提示文字过滤=0 结果) → 命令面板
    (Ctrl+K)在全 UI 无任何可发现性入口——三段各自成立,串起来走不通
```

另有 X-6/X-10 两个上轮修复的"半程残留"(info 高度自适应未接重布局触发、空闲倒计时取消后文案冻结),Apps 页最小窗控件重叠(980<1068 阈值)依旧。

**评分:交互设计 7.5/10**(上轮 7;新功能方向全部正确,落地完成度约 70%,P1 出在一个 30 行对话框里)。

## 1. 问题清单(新发现 X-26 起,按严重度)

### P1

**X-26 开发缓存根对话框:多行输入在“确定”时被静默整体丢弃,且清空既有配置**
- 位置:[V] `C:\tjf\github\MiniSys\MiniSys\src\MainWindow.cpp:877` `if (ch == L'\n') flush;` 与 `:1011` `if (ch == L';') flush;` —— 两处 lambda **只写了名字没写调用括号**,是合法的"废弃值表达式",MSVC 静默编译通过。
- 后果链 [V]:IDOK 时多行文本(`D:\a\r\nD:\b`)不走行分隔,`cur` 累积成 `D:\aD:\b` → `joined` 无 `;` → OnDevCacheRoots 校验时 `D:\aD:\b` 的 `[0..2]` 恰好是 `D:\` 通过前缀检查、`is_directory` 失败 → dropped=1 → `settings_.devCacheRoots = ""`(**原有配置一并清空**)→ 提示 "✓ 已保存开发缓存扫描根（忽略了 1 个无效/不存在的路径）。"——**成功符号 + 错误事实**。单行输入不受影响;“浏览添加…”按钮鼓励的多次追加(第二次起必现)恰好是触发路径。第二处 `:1011` 同病,即使修了第一处,校验端也不会按 `;` 拆分。
- 改法:两处补 `()`(共 2 字符);顺手在 IDOK 前做行级 trim(粘贴路径常带引号/空格)。工作量 S(10 分钟含验证)。
- 附带(并入本项):校验只在 OK 后一次性进行,丢弃行只报数量不报内容,框内无行级反馈;建议 IDOK 时就地校验并在对话框内标红无效行 [P3 打磨]。

### P2

### 4.4 竞品一句话对标(各一条,不越界)

- **Everything**:把生效中的 `ext:/folder:` 过滤做成搜索框下方可点 ✕ 的 chip 行(上轮蓝图 #4)——MiniSys 的过滤唯一可视痕迹是框内文本,菜单勾选只开菜单时可见。
- **WizTree**:文件夹分析树节点加"占用条"(bar-in-cell,owner-draw)——大小数字旁一根按占比的横条,定位空间大户的速度差一个数量级。
- **CCleaner**:垃圾页空态给一个大号『分析』CTA + “上次运行:X 前,清理了 Y”——把现有“上次扫描(缓存)”时间线升级成首次行动入口。
